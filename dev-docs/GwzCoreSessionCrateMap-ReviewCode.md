# Crate map review — architecture (Code axis)

Object: `dev-docs/GwzCoreSessionCrateMap.md`, 143 lines, SHA-256 `eac8e018eff25e360c957304bb529dc5f121f0052ac37967ec348e01ad688eab`, verified at start and end; root `621f671`, gwz-core `4a0b7c8d`, gwz-py `a342b95`. Verdict: **NO-GO**. P0 0, P1 0, P2 3, P3 6.

## Findings

**P2-1 — Transport crates: forbidden edges and orphaned shared modules.** §1 "Roles and edges"; §4 table (no dependency column). Rule: `role_edges` (local_clone_inventory.json) and LBT-003: every role depends only on contract and pure crates; LBT-001 rejects an unclassified library. Facts: `stream_io::BlockingStream` (built on `gwz_transport::stream`) is used by ssh_worker/ssh_endpoint, https_local, request.rs/session.rs and both `*_remote` files; `shared_reservation::Authority` by ssh_local/ssh_endpoint, https_pool/https_worker and session.rs/https_endpoint.rs. The map has no transport contract crate, so each lands in one implementation crate the other must import; gwz-endpoint-registry (integration) builds gwz-endpoint-instance (integration); the two implementation crates would implement the instance crate's `Engine` port; gwz-transport has no recorded role. Consequence: no cut of §4 passes the gate the map adopts, and CS7.1 is redone. Correction: a transport contract crate (BlockingStream, the authority and engine ports, GitService), a dependency column, gwz-transport classified as an allowed pure edge, and the core adapters that bind `Engine` to the two implementations.

**P2-2 — Secrets do leave core.** §3 ("everything that touches … secrets"; "the environment snapshot and its secret handling therefore stay in core") against §4 (gwz-https-endpoint takes "the HTTPS files except https_remote"; gwz-ssh-endpoint takes "keys") and §5 (CS7.15 → transport crates). Facts: https_auth.rs `Config { environment: Vec<(OsString, OsString)> }` spawns `gh` with `env_clear().envs(config.environment)` (:29-32, :326-327), and CS7.15 keeps that spawn "with env_clear() plus the snapshot"; ssh_key_container/ssh_key_snapshot hold private key text (reuse §12, decision 10). Consequence: the whole snapshot becomes a crate's API input, reviewed "against its own API and README"; the map's boundary statement is false. Correction: core owns a helper-spawn port (core spawns `gh` from the snapshot and hands the crate the child's pipes and a kill handle); name gwz-ssh-endpoint's key-text surface as the one secret-bearing crate API, under per-step dual review; amend §3.

**P2-3 — `NEXT_POOL` has no legal replacement.** §4 "The counters go … gwz-transport's NEXT_POOL"; §5 owns only T1–T5 in gwz-transport. Rule: gwz-transport depends on nothing (contract §5.7; gwz-transport/AGENTS.md; empty `[dependencies]`). Fact: `pool_id` (machine.rs:80-99) stamps every `ConnectionId` (allocation.rs:66). Consequence: gwz-ids, published from gwz-core, cannot be gwz-transport's dependency without inverting the publish order and the boundary job's `reconciled_commit` rule; the alternative has no owner. Correction: `Pool` takes its ID, or a source, from the host at construction; add that step to the pool checkpoint (CS7.2–CS7.6).

**P3-1 — IdSource's uniqueness claim is unsupported; the temp-name owners are unnamed.** §2 gwz-ids row; §6.2. Fact: `unique()` claims uniqueness "across contexts and processes" from `new(prefix)` plus a counter, but two contexts with one prefix start equal; today's names (`yaml.{pid}.{seq}.tmp`, `.{name}.tmp.{pid}.{seq}`) are process-unique only through the static. family-store opens its temporary with `File::create` (publish.rs:115), which truncates; `write_atomic_verified` is the pinned single-caller seam (check_checked_artifact_boundaries.py `NEUTRAL_RAW_WRITE_FLOOR`). Consequence: a cross-context collision in one directory clobbers an in-flight temporary; the writers are lock-serialized today (inferred), so the claim is wrong before the code is unsafe; step 2 re-pins a protected seam without saying so. Correction: state the unique component (OS-random or a caller-supplied unique prefix), which context owns each of the four sources, and the re-pin.

**P3-2 — Removing `CROSSING` is asserted, not designed.** §2 note. Fact: gate.rs's thread-local catches a crossing or revoke of any gate from a closure or callback; `OperationGate` is `Clone`, so a closure can capture a gate and cross it without the passed `GateScope`. Consequence: same-gate re-entry deadlocks on `crossing: Mutex<()>` instead of panicking, and close's bound (§8 step 5) is missed, the hazard S-P3-3 closed. Correction: name the mechanism (the gate records its crossing thread; closures get a non-Clone scope) and what stays undetected.

**P3-3 — §7 omits text the map contradicts.** Contract O9 ("carry no session-relevant state or are imposed by a dependency") and §5.7's counters row ("The counters are permanent allowlist entries"); GWZDesign's paired paragraph, authoritative under gwz-core/AGENTS.md; plan §3.0's ratchet sentence (a marker, flag or counter may be permanent, "as CS1.4's thread_local CROSSING is") and §5.4's "stay permanent" list; CS3.1/CS3.5's "Budgets stay process-wide on the legacy path" against §2's "one supervisor … instead of keeping two"; server §2's first row and §4, which put the walk, sandbox rule, hosts and launcher in core, not only `ServerAddress`. Consequence: a step following the plan's text lists a counter `permanent` or keeps the second supervisor. Correction: list each.

**P3-4 — Two roles do not fit.** §2: gwz-server-os, "implementation", implements no named contract (LBT-002); gwz-server-policy, "pure", consumes a file-system port, which the inventory's roles call integration ("pure: no I/O"). Consequence: the classifier rejects both, or admits them without rationale. Correction: gwz-server-os as an integration crate over ports it owns; the OpenSSL scan behind core, or the policy crate reclassified.

**P3-5 — Build and publishing claims skip tooling that pins fourteen.** §1, §4 "Where these crates live", §6.5, §8.3. Facts: check_crate_versions.py has `EXPECTED_CRATES = 14` ("a fifteenth … is drift"); check_local_clone_boundaries.py reads one `cargo metadata` at gwz-core's root and refuses a classified crate outside that workspace or declaring `[workspace]`, so `gwz-core/transport/` is outside every gate; prepare.py adds only gwz-transport by path; gwz-transport is `publish = false`; activation puts five transport crates and gwz-transport into gwz-core's ordinary graph, so each needs a registry version before gwz-core 1.1.0 publishes (crates.io plan §1). Consequence: the ordinary crates fail S1.2's gate on landing; the transport workspace is ungated; eleven names need first publications, not six. Correction: name the check, release-script and prepare.py changes in §6.1; give the gate a second root; count the names.

**P3-6 — "tests alone, without git2" fails for the HTTPS suite.** §1; §4 gwz-https-endpoint row. Fact: https_worker_tests.rs (911 lines) drives the worker through git2 (`Repository::init`, `RepoBuilder`, `FetchOptions`, :297-442), as does https_remote_tests.rs. Consequence: the suite cannot move with its code under the map's rule, and left in core it tests the crate from outside its fast target (LBT-010). Correction: say where it lives, or declare git2 a dev edge of that crate, as repo-inspect does, and drop the blanket sentence.
