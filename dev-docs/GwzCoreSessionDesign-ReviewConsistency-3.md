## 1. Findings

### [P3-28] §15.1 still says a stopped-waiting call's reply "is dropped", contradicting §10's rule that result and response replies are never dropped
- **Location:** §15.1 line 559 ("A call whose client stops waiting still completes, and its reply is dropped") versus §10 line 456 ("A result or response reply is never dropped, even when its waiter was cancelled or its loop has closed") and §15.12 line 636 ("Replies for closed loops are dropped, except result and response replies").
- **Violated invariant:** one rule per fact; every statement the revision 3 diff touched must agree with the unchanged verification list.
- **Reproduction:** a test writer implements §15.1 for an `operation.result` call whose task is cancelled and asserts the reply is dropped; the same suite's §15.12 test asserts `operation_result` from another loop returns it from the bridge's view. One implementation cannot satisfy both readings.
- **Impact:** §15's own items conflict for the two call kinds revision 3 singled out; the P3-25 correction is incomplete in the verification list.
- **Required correction:** §15.1: "… and its reply is dropped, except a result or response reply, which the bridge keeps (§10)."
- **Closure test:** the §15.12 closed-loop result test, plus §15.1 rerun for a cancelled unary call only.

### [P3-29] The libgit2 own-reads exception is scoped to "ordinary builds" in four places but §5.8 and GWZDesign extend it to transport builds' native remotes
- **Location:** O9 line 82 ("In ordinary builds libgit2 still reads some process state itself, which §5.8 names"); §5.6 line 291 ("except through what libgit2 reads itself in ordinary builds (§5.8)"); §16 line 646 ("In ordinary builds, libgit2's own SSH agent connection and configuration discovery read the process"); GWZRequirements line 16 ("In ordinary builds, the reads libgit2 makes itself are excepted, as the contract states") — versus §5.8 line 355 ("They apply equally to the remotes libgit2 handles natively in transport builds") and GWZDesign line 13 ("which still governs ordinary builds and libgit2's native remotes. There libgit2 also still reads the SSH agent socket and the home directory itself"); §5.6 line 297 already names `git://`, `http://` and `file://` as native in transport builds.
- **Violated invariant:** the paired paragraphs make the same claims as the contract; build-dependent statements stay aligned (§16 line 658).
- **Reproduction:** in a transport build, open a session, change `HOME`, then fetch from an `http://` remote. §5.8 says libgit2 reads the changed home directory's global configuration; O9, §5.6 and GWZRequirements say the exception does not apply in transport builds, so the read violates their MUST NOT as written. §15.8 line 605 ("In transport builds, after `open`, changing `HOME` … leaves a later operation's endpoint configuration equal to the one captured at open") is unsatisfiable when "a later operation" targets a native remote.
- **Impact:** the exception's scope depends on which section is read; the requirement and its test cannot both be met for native remotes in transport builds.
- **Required correction:** in O9, §5.6 line 291, §16 line 646 and GWZRequirements, "in ordinary builds, and for the remotes libgit2 handles natively in transport builds"; scope §15.8 line 605 to remotes gwz-transport handles.
- **Closure test:** §15.8 line 605 restricted to an `ssh://` or `https://` remote, plus a documented-exception assertion for an `http://` remote in a transport build.
