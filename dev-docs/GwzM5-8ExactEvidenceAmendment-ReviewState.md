## Findings

**F1 [P2] — Clause A's "agree by construction" holds only for paths the recovery-grade checkout actually rewrites; the amendment's residual enumeration omits the dominant real-Windows exposure.** `disable_filters` is smudge-side only (the amendment's own libgit2 citation: `GIT_FILTER_TO_WORKTREE` skipped; comparison-side clean filtering stays active), so a recovery checkout rewrites only paths differing between the two trees. Every path materialized earlier by a *filtered* checkout — the user's original clone, forward integration (`merge_prepared` `checkout_tree` / `fast_forward`, listed "untouched" in the §2.A table with the reason "verified by filter-aware state only") — keeps CRLF on disk. But those paths *are* subsequently judged by the raw-byte model: `observe_v1_participant_rollback` / `verify_v1_no_mutation_participant` / `terminal_v1_participant_is_exact` compare the **whole tree** blob-exact (`abort/participants.rs:95-133, 135-165, 167-192` → `preservation_image.rs:152-199`). Concrete scenario: Windows, `autocrlf=true`, post-A1; ordinary clone (CRLF worktree); any member with one file unchanged between `resulting_commit` and `before_commit` — reverse entry classifies the not-started state `Ambiguous` (raw CRLF ≠ LF blob), so checked rollback never starts; and where it does start, the After re-verification fails on unchanged-but-smudged paths — the exact class-A signature surviving Clause A. The new repro cannot see this (its worktree is LF throughout and its only tracked delta is the one file the rollback rewrites), and the fixture families produce LF worktrees, so CI stays green. Fail direction is closed everywhere (availability loss, never wrong evidence), and today's production (v0, pre-A1) doesn't reach these observers — but the amendment's normative sentence ("Any libgit2 checkout whose result is subsequently judged by the raw-byte exact-evidence model runs with filters disabled") is contradicted by its own site table, and §3's affected-behavior statement doesn't say that ordinary Windows-CRLF worktrees remain unsatisfiable for the raw-byte model regardless of this fix. Remediation is documentary: extend the residual/affected-behavior section to name filtered-materialization exposure generally (forward checkouts and porcelain clones, not just `stash_save`), and record that closing it needs its own reviewed decision (e.g., recovery-grade full re-materialization at rollback entry, or a filtered-compare mode).

**F2 [P2] — Clause A's cleanliness argument is CRLF-specific; for repos with clean-filters non-idempotent on blob bytes (git-crypt class), the delta converts previously-working production v0 aborts into post-mutation failures on every OS.** §3 claims unconditionally "git status remains clean", reasoned only from CRLF idempotence. `disable_filters` bypasses *user smudge drivers* too (disclosed in Clause A), so a rewritten path receives raw blob bytes (e.g., ciphertext). Builtin filters are safe (crlf/eol/ident idempotent on blob bytes; LFS pointers round-trip clean). But where `clean(blob_bytes) != blob_bytes` (encrypt-on-clean filters), the rewritten path is status-dirty; `verify_merge_result` then fails **after** `transaction.commit()` in `set_branch_target_checked` (`merge_recovery.rs:214-218`) or after the abort restore — and this path is production-reachable *today* via the v0 abort flow (`abort/participants.rs:13-67` → `runtime` → `set_branch_target_checked` / `abort_merge`). Pre-amendment those aborts completed (filtered write → clean status). Post-amendment: ref moved, then loud `GitCommandFailed`, operation halts recovery-required; retry hits the idempotent arm (`merge_recovery.rs:189-196`) and fails the same verify — wedged until manual intervention. No silent corruption, but a real, undisclosed behavioral regression class. Remediation: state the soundness precondition (clean-idempotence on blob bytes) in the amendment, enumerate the builtin filters as satisfying it, and route the foreign-filter policy (refuse recovery-grade checkout when non-builtin filter attrs cover rewritten paths, vs. accept the wedge) as an explicit open decision. Also fold in the LFS-shaped user surprise (pointer bytes on disk post-rollback; porcelain re-checkout restores content).

**F3 [P3] — B′'s disclosed scope understates its reach: `verify_merge_result` also post-verifies forward integration.** Callers at `merge_prepared.rs:248, 261, 335` (checked upstream fast-forward, up-to-date, post-true-merge) now tolerate private-area untracked residue too. Direction is benign — it heals a pre-existing Windows failure mode where a *forward* root merge would error after mutating — but the amendment frames the predicate strictly as the rollback's "paired post-verification". One sentence in §2.B′ fixes it.

**F4 [P3] — Untouched siblings are a correctly-flagged latent wedge; keep them tracked.** (a) `validate_abort_index_and_worktree` / `validate_resolution_index_and_worktree` permanently refuse conflict abort/resolution in any anchor-bearing repo; safe today only because anchors are root-only and the root never enters native-merge conflict paths — both premises verified in this tree, neither pinned by a test. (b) v0 preservation planning is status-based (`stash_for_merge_preservation` preservable check, `preservation.rs:213-220`): on Windows an anchor-bearing root plans preservation forever and can create an anchor-only stash whose post-amendment decoded image certifies nothing; v1 planning is image-based and immune (and its bundle classifier even rejects nothing-dirty stashes, `checked_bundle.rs:160-171`). All fail-closed; acceptable to defer given v1 supersession, but the amendment's flag list should note (b)'s anchor-only-stash consequence explicitly.

**F5 [P3] — Coverage changed under an unchanged preimage frame version.** `PREIMAGE_FRAME = "gwz.merge-preservation-preimage/v1\0"` (`preservation_image.rs:7`) still frames the post-amendment encoding, so equal-frame hashes recorded before/after the boundary are incomparable-by-design rather than distinguishable-by-version. Safe because every comparison is fail-closed equality and no released writer exists (Q2), but the acceptance-time annotation of the contracts should state the discontinuity so a future reader doesn't treat v1-frame hashes as a stable cross-version identity.

**F6 [P3] — The recorded `stash_save` residual has no failing sentinel.** With the fixture autocrlf pins (f2fceaf), no CI lane can reproduce the residual; recommend a Windows-matrix expected-fail/ignored sentinel or an explicit entry in the matrix classification doc so the follow-up decision the amendment promises has a live tripwire.

Positive verifications worth the record: capture/decode/overlay are now uniformly exclusive, including tracked private paths, matching the overlay's pre-existing stance; decode's dirty summary is computed post-exclusion, symmetric with capture's; B′ deliberately stayed out of `status()` (porcelain parity intact, `repository.rs:192`); the three repro tests pin exactly the three amended clauses; and the amendment's restore/pop-safety and stale-anchor-Invalid claims check out against `handle_stash/commands.rs` and `platform.rs`.

## Verdict

**NO-GO** as it stands — on the amendment document, not the code. The code delta is sound on the state axis: fail-closed in every divergence case, no fault edge moved, tri-state observations total, symmetric image coverage, and honest cross-version disposition. But F1 and F2 are P2s against the amendment's semantic claims: "agree by construction" and "git status remains clean" are both overclaims whose counterexamples are mechanically derivable from the delta itself, one of them a production-reachable v0 regression class, and CI is structurally blind to both. This program's currency is exact claims; a platform-semantics amendment must not freeze inexact ones. Remediation is cheap and doc-local (extend Clause A's residual enumeration per F1; state the clean-idempotence precondition and foreign-filter policy per F2; one-line scope fix per F3), after which this becomes a GO without re-running anything beyond a read of the revised text.
