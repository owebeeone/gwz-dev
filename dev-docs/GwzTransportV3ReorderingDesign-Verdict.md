Initial independent [Consistency](GwzTransportV3ReorderingDesign-ReviewConsistency.md) and [Safety](GwzTransportV3ReorderingDesign-ReviewSafety.md) reviews both found that valid late completion after local retirement could fail unrelated streams. The corrected committed tuple received independent [Consistency re-review](GwzTransportV3ReorderingDesign-ReviewConsistency-1.md) and [Safety re-review](GwzTransportV3ReorderingDesign-ReviewSafety-1.md), both **NO-GO**. Consistency found a new architectural gap: after a locally retired Opening receives late Opened, normal established traffic can arrive, but the shadow-state rule cannot validate it; its Opened→Closed test skips a required Close predecessor. Safety found a separate new architectural gap: `WrongSession` only protects a profile-3 receiving port; an overlapping profile-2 or unbound replacement can still return `Ok` for an S1 opening it discarded, unless the host checks generation affinity before acknowledgement.

These are further architectural roots after the first round's local-retirement and cross-generation identity failures. Accordingly, no second remediation patch, authoritative-design update, transport code change, Python activation or release claim follows from this object. The earlier stopped delivery amendment remains stopped.

The next operator decision is **redesign or consciously accept the risk**. A redesigned object should treat admission acknowledgement as a host-owned, exact-generation receipt across *all* profiles, and treat a retired stream as a bounded, non-authoritative continuation of its actual peer state machine. Those are design directions, not approved requirements. A new object needs its own settled tuple and dual review before implementation.
