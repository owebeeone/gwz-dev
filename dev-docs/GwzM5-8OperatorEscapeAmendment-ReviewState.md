## 1. Findings — P1 (material semantic gaps; block acceptance)

### [P1-1] The consent-digest rules are mutually unsatisfiable for any invocation that writes more than one consent-carrying row — the collapsed pair is unconstructible as specified

The amendment binds four clauses that cannot all hold:

- §2.2 :385 — `record_sha256: String, // digest of the source bytes the manifest was printed from`.
- §2.3.2 :575 — `MarkOwnerUnrecoverable` "appends **exactly one** `OwnerDispositionV1` side" per transition (one write per side).
- §2.2.4 rule 7 :510-513 — a collapsed pair's two side rows "must carry the same `consent` (**identical operator, timestamp, digest, token**)".
- §5.5 :1250-1252 — `consent.record_sha256` "is validated **once**, at the consuming edge, **against the exact source bytes the transition is applied to**".

Concrete sequence: `--give-up-on libs-a:both --confirm <token(D0)>` under `repository_missing`. Mark 1 (preservation side) applies to bytes with digest D0 — §5.5 validation passes. That write changes the record; the bytes are now D1 ≠ D0. Mark 2 (rollback side) must, per rule 7, carry the *identical* digest D0 — and per §5.5 must validate D0 against its own source bytes D1. **Both cannot hold; the only record shape rule 7 accepts is one §5.5 rejects.** The same contradiction hits every multi-side invocation (§4 rows 4/5 explicitly show sequential mark writes), and the entry/terminal consents: §2.3.2 requires "fresh digest-bound consent" at `BeginRollbackOverridden` and `AbortOperationOverridden`, but in the no-crash single-invocation flow (§3.3.3: one manifest, one `--confirm`) those edges run after many tool-authored rewrites (marks, ordinary rollback actions), so their consent digest is either the stale manifest digest (violating §5.5) or a fresh digest the operator never saw (violating §3.3.3's "consent is bound to exactly the bytes whose consequences were shown"). The amendment never says which.

**Remediation (small, text-only).** Define a **consent round**: `record_sha256` is always the digest the manifest was printed from (the round anchor); the round is validated once — token against current bytes at invocation entry, under the mutator lock and mutation lease held for the whole invocation — and every consent row written by that invocation carries the round anchor as inert provenance thereafter (this is already §5.5's "thereafter it is inert" posture; extend it to the second and later writes). Restate §5.5's validation sentence accordingly ("validated once, at the round's first consuming edge…"), define "fresh" in §2.3.2 as "of the current round" with a crash ending the round (§4 row 4's re-earn already says this), and rule 7 then holds naturally. Alternative: give the collapsed mark a two-side atomic footprint (one transition writes both rows) — but that still leaves the entry/terminal digest question, so the round definition is needed regardless.

### [P1-2] Ordinary `AbortOperation` CAN terminalize an overridden record when only preservation-side marks exist — the "ordinary path can never terminalize" claim is derived, and the derivation is false

§2.3.4 :610-614: ordinary proofs "remain over the complete domain and are **therefore** *unobtainable* once any mark exists — so the ordinary path can never terminalize an overridden record." The "therefore" holds for rollback-side marks (a marked rollback side has no terminal row, so `VerifiedRollbackExhausted` — "covers every participant and exact selected-root baseline", TransitionDesign §6.1 :448 — fails) and for `VerifiedPreservationExhausted` at entry. It is **false at the terminal edge for preservation-side-only marks**:

1. Preserve-abort enters `Preserving`; libs-a's backup ref is destroyed (U3); operator marks `libs-a:preservation` only (narrower basis — §3.3.4 forbids collapse).
2. `BeginRollbackOverridden` consumes `VerifiedPreservationExhaustedOrMarked`; state `RollingBack`, `overridden_entry` written.
3. Every participant's **rollback** side is unmarked and healthy; the ordinary machinery rolls every one back exactly (real `RolledBack`/`Aborted` rows), root baseline restored exactly.
4. An ordinary `--abort` request now reaches the terminal edge: `VerifiedRollbackExhausted`'s stated obligation is satisfiable over the complete domain — nothing in its frozen definition, in the dispatcher, or in this amendment consults `operator_override`. Ordinary `AbortOperation` fires: `state: Aborted` **without `overridden_abort`**.

That shape is structurally legal under §2.2.4 rule 8 (which constrains only *presence* of `overridden_abort`), passes `validate_v1_lifecycle` (all participants terminal), and directly contradicts: §4 row 6 :1140 ("Ordinary `--abort` resumes the tractable owners' rollback … **and then refuses at the terminal edge**"), §2.3.4's headline claim, §5.6, and §8 test 7 :1559-1564 (which as written would fail against the §6.1 rows the amendment keeps "byte-for-byte"). It also breaks the rendering dichotomy: §2.5.3/§3.3.6 define rendering for "an overridden abort" (terminalized by the overridden edge) and for open records with dispositions — a *terminal* record with dispositions, `overridden_entry`, and a plain abort is in neither class, and the record's terminal consent slot never records the operator's terminal-time blessing of the marked-side table.

**Remediation.** Make the unobtainability **definitional, not derived**: one normative sentence in §2.3.4 and in the §7 item 3 TransitionDesign note — "a bound `VerifiedRollbackExhausted`, `VerifiedPreservationExhausted`, or `PreparedRollbackEntry::FromPreserving` is **not constructible** while any `operator_override` disposition exists; only the §6.10 edges may terminalize or enter rollback on such a record." (The §7 item 3 note's current phrasing "are therefore unobtainable" imports the false derivation into the frozen contract — change it there too.) Test 7 then passes as written.

### [P1-3] The frozen cursor-derivation sentences are never amended, so the post-mark shapes the amendment mandates are decode-invalid — ordinary rollback work behind a mark is impossible as frozen

§3.3.2 :905-910 (normative): "cursor and prefix derivation **consume** disposition rows as retirement facts." §4 row 4 :1138 promises "cursor derivation skips the marked side so ordinary rollback work on *unmarked* owners proceeds." But §7 amends only TransitionDesign §6.7's preservation-cursor paragraph (item 3). Three frozen sentences that *define* the cursors are left untouched and contradict the refined rule:

- **ActionJournal §2 :178-181**: "For rollback, owner/kind agreement includes the exact deterministic current cursor **derived from durable participant terminal states, publication evidence, selected-root membership, and pending phase; a wrong or later owner is invalid at decode.**" Concrete: mark `libs-a:rollback` in `RollingBack` (journal retired by the mark), then `BeginParticipantRollback` for the next owner libs-b. libs-a has no terminal state, so the frozen derivation says libs-a is still the current owner; libs-b's pending action is "a later owner" → **the write's own post-write re-decode rejects it** (RecordContract §8 :414-417 rereads through the decoder). Row 4's promise is unimplementable against the unamended contract.
- **ActionJournal §2 :185-192** (the D3-amended prefix sentence): a pending preservation action's prefix proof is "by durable completion facts where present, and by exact bound live observation where absent" — a closed two-source list. A marked earlier preservation position is neither, so no later tractable owner can be classified behind a mark, defeating §3.3.5's "tractable preservation owners are still driven to completion" in exactly the U3/U1 cases that motivated the entry edge.
- **TransitionDesign §6.6 :648-651**: "The reverse cursor is fully derivable from participant terminal states, publication rollback evidence, selected-root membership, and the exact pending phase." Same defect as the first.

**Remediation.** Add to §7 item 2 and item 3: each of the three sentences gains the disposition input (e.g. "…durable participant terminal states **or operator-override rollback-side dispositions**…"; "…by durable completion facts where present, **by an operator-override mark on that owner/side**, and by exact bound live observation where absent…"). This is the same class of edit D3 performed on the same §2 sentences and is required for the amendment's own §6.1 precedence (durable fact → live proof → mark) to be true in the frozen texts.

### [P1-4] The overridden terminal's flagship durable shape violates the existing v1 checked-record legality rule "Aborted ⇒ every participant rollback-terminal" — the write fails its own post-write verification, and the amendment never amends that rule

§2.3.2 :577: at `AbortOperationOverridden`, "**marked participants keep their last honest state** (`Merged`, `Conflicted`, …) — no fabricated terminal outcome." The implemented I2 validity set rejects exactly that shape: `model/v1/validate/lifecycle.rs:56` — `OperationState::Aborted => states.iter().copied().all(is_rollback_terminal)` (`Aborted | RolledBack` only), error `TerminalRollbackMismatch` "aborted record retains an unfinished participant or action". Consequences if accepted as-is: the terminal rewrite's mandatory re-decode (RecordContract §8 :414-417) rejects the new bytes, so **the overridden terminal edge can never commit** — in precisely the U1 flagship case (deleted repository ⇒ rollback-side mark ⇒ participant stays `Merged`/`Conflicted`); and had it committed, every later open/archived decode of the record would fail. The amendment cites `model/lifecycle.rs:54-64`/`:83-117` (the enum transition tables) but never cites, quotes, or amends the aggregation rule in `validate/lifecycle.rs`, and no §7 delta or §8 test row legalizes the shape (§8.3(b) tests only the healthy shape where rollback ran exactly).

**Remediation.** Declare the validity-set delta explicitly, in the §7 item 3 §6.10 block (and mirror in §8 tests): "under `state: Aborted` with `overridden_abort` present, a participant is legal in a non-rollback-terminal state **iff** its rollback side carries an `operator_override` disposition; with `overridden_abort` absent the existing all-rollback-terminal rule is unchanged." Note the same for the archived-read direction. (The v0 `ParticipantState::transition` table needs no change — marked participants undergo no participant transition.)

### [P1-5] §2.2.4 rule 8's terminal test is not decidable from durable facts for live-proven-retired preservation positions — depending on reading, the terminal edge deadlocks or silently waives a consent obligation

Rule 8 :514-519: `overridden_abort` "requires, for every owner in the closed domain, that each *applicable* side is either **proven-retired by ordinary evidence or marked**." §3.3.6 :1033-1037 derives preservation-side applicability from "state is or was `Preserving` …, or a preservation evidence row exists." Two unpinned points break decidability:

1. **Positions retired by live proof leave no durable witness.** The entry edge's `VerifiedPreservationExhaustedOrMarked` (and ordinary exhaustion) accepts live-proof retirement; D3 §4 item 2 explicitly preserves durable-fact-free shapes (pre-D3-implementation records — and the tree today has **no** marker implementation, P3-1 — plus D3's own acknowledged crash window "a crash after a position was live-proven but before its marker write"). At the terminal edge such a position is neither "proven-retired by ordinary evidence" (no row) nor markable (`--give-up-on` of an observable side is a typed refusal, §3.3.5) — **rule 8 is unsatisfiable and force-abandon deadlocks** for a record whose preservation was actually fine. The escape wedges in its own target scenario class.
2. **"is or was `Preserving`" has no stated durable derivation** once the state is `RollingBack` and no evidence row exists (`overridden_entry` does not record its origin). Under the alternative per-owner reading (applicability = that owner's row exists), the same corner silently deems the side inapplicable and rule 8 passes — no deadlock, but the legality rule's outcome now depends on which reading an implementer picks, and an archived overridden record can be **write-legal under one reading and read-invalid under the other**.

**Remediation.** Pin both: (a) applicability's "was Preserving" must be a stated durable derivation (e.g. `overridden_entry` gains an origin field, or applicability is defined solely over per-owner durable facts: evidence row ∨ preservation-side disposition); (b) rule 8's preservation-side test gains a third arm mirroring the entry edge — "proven-retired by ordinary evidence, marked, **or exactly re-proven live by the bound terminal proof**" (i.e. `VerifiedOverriddenRollbackExhaustion` embeds a preservation exhausted-or-marked re-proof rather than a purely structural check), with the archived-read form of rule 8 stated to trust the recorded edge rather than re-deriving live facts.

### [P1-6] The quarantine sidecar's lifecycle after restore is unspecified — a stale sidecar breaks the crash-row-2 detection premise and can wedge or corrupt the *always-available* rung of the ladder

§3.2 specifies restore of the record bytes only; the sidecar's fate is never stated. §3.1 :802-806 makes the sidecar write the **first** step of quarantine ("write the sidecar atomically first"), and §4 row 2 :1136 keys crash detection on "the sidecar exists **with a matching digest**" — a premise that only holds if every existing sidecar belongs to the current quarantine attempt. After a park → repair → restore → later re-wedge → re-quarantine cycle (an expected operational loop — §3.2 calls restore "the repaired-world re-entry" and allows quarantine of override-carrying records), the old sidecar for the same stem still exists with a digest that no longer matches:

- If the fresh quarantine **overwrites** it, an immutable consent artifact (§2.2.4 rule 9's discipline; §7.3 of the design: sidecars "immutable once written") is destroyed, and "No quarantined byte is ever overwritten" (§3.1 :816) is violated in spirit or letter.
- If it **refuses**, quarantine — the rung §5.3 of the design promises is "always available" and the U-table's universal fallback — is unavailable for exactly the records most likely to need it twice.
- Either way, §4 row 2's idempotence detection misclassifies the stale sidecar (mismatched digest: crashed attempt? previous episode?), and the §7 item 4 arbitration's "quarantine present" predicate is undefined for a sidecar-without-record orphan.

There is also a missing crash window: **between the restore rename and any sidecar disposal** — absent from the twelve-row table, which claims per-edge exhaustiveness.

**Remediation.** Specify the sidecar lifecycle: on successful restore the sidecar is removed (or renamed to a retained history name) in the same operation, with the new crash window added to §4 (orphan sidecar ⇒ inert, superseded by the next quarantine's fresh write; status ignores or reports it as historical); extend the §3.1 destination-collision suffix rule to the sidecar name; define the mismatched-digest-sidecar case in row 2 (belongs to a different episode ⇒ supersede, never adopt). Add these shapes to §8 test 5.

### [P2-1] §4 row 10 and the §7 item 4 arbitration row assign different semantics to the same both-copies shape

Row 10 :1144: both copies with identical bytes ⇒ "the open copy is authoritative and the quarantine copy is retained" (a legal converged outcome). §7 item 4 :1458-1460: "quarantine present + open present → **typed contradiction**, no mutation" (unconditional). ### [P2-4] The GC forget-refs consent anchor and the stale-token refusal code are unpinned
