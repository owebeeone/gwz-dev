## 1. Findings

### [P3-8] §4's outcome table promises that a cancelled or timed-out check returns the connection to idle, but the connection is now the binding's lease, and the pool closes a cancelled owner's leased entries; the text does not say which path returns it and which closes it

**Location.** §4, line 90: "While the check runs, the connection is that binding's lease. It is released to idle if the check is cancelled or times out". Outcome table row 3 (108): "The request is cancelled, or its deadline passes | returned to idle | fails `Cancelled` or `Timeout`". §8 (176): "The binding's cancel touches its own mux, table entries, leases and waiting pool requests; `cancel_session` on the binding's session ID is the backstop when a binding is abandoned (POOL/lifecycle.rs:80-107)." T3 (287) and T1 (285), which make the under-proof entry a leased entry with the binding as owner.

**Violated invariant.** A design sentence must be implementable on the interface it cites. `cancel_matching` (`pool/lifecycle.rs:88-108`) fails the owner's waiting requests and then starts closing every entry in `State::Leased` whose `owner` matches, with `CloseReason::Cancelled` (lines 97–107); `cancel_operation` and `cancel_session` both route through it. A lease can return to idle only through `release(lease, Disposition::Reusable)` (113–129), which the host must call before any `cancel_*` reaches the entry.

**State sequence.** Binding B checks out idle connection c whose last lessee was A; the proof job starts; c is B's lease (§4). B's operation token is cancelled. Reading 1, the natural one for "the binding's cancel touches … its leases": the host calls `cancel_operation(B's owner)`; `cancel_matching` finds c leased by B and starts closing it. Row 3 says c is returned to idle; it is closed. Reading 2, the backstop: B is abandoned; the host calls `cancel_session(B.session)`; the same lines close c. Row 3 is false on this path whatever the host does, because the pool, not the host, decides. Only reading 3 — the host releases c `Reusable` on the proof's cancellation *before* cancelling B's pool work — yields "returned to idle", and nothing in §4 or §8 says so.

**Impact.** Bounded and fail-safe: a healthy connection is closed instead of returned to idle, costing one handshake for the next operation. But the text states one outcome and the cited interface produces another on two of three implementations; §15 item 6's "idle connections survive" does not distinguish the under-proof connection, so the discrepancy would not be caught. This is a text defect exposed by P2-1's remedy, not a defect of that remedy.

**Remedy (one clause; not architectural).** In §4 after "It is released to idle if the check is cancelled or times out": on cooperative cancellation or a passed deadline the host releases the lease `Reusable` before it cancels the binding's pool work, so the connection returns to idle; when the binding is abandoned and `cancel_session` runs as §8's backstop, the pool closes the lease with `Cancelled`, like any other lease. Adjust row 3's connection cell to "returned to idle (closed, if the binding is abandoned)".

**Closure test.** §15 item 6 gains one case: cancel B's operation while its proof job is pending; the connection returns to idle and A's next request reuses it; abandon B instead (channel closure with no cancel) and the connection is closed with `Cancelled` while every other idle entry survives.

## 3. Risks and next action

Residual, below the finding bar:
1. **T4's release-path reason.** "closed through its lease's release path with the same reason" needs a `Disposition` arm (or equivalent) that maps to `CloseReason::Revoked`; today's `release` knows only `Reusable`, `Unproven` and `Discarded` (`lifecycle.rs:127-136`). T4's scope covers it; naming the arm would remove the inference.
2. **CS:477 as the citation for gwz-py's drop.** CS:477 says the finalizer closes the channel and joins the pump within the close bound; it does not say the process-wide host context is dropped at interpreter exit. That rests on CPython finalizing module globals, which is not guaranteed for every object. The consequence is benign (instances closed by process exit; no report was promised), and CS4.5 owns the exit path; TR1.4b should state it.

4. **The binding's own threads.** §2 now cites only the link thread (955–1007) for "driver-session and link threads"; the driver session is stepped by the request's executor rather than a thread of its own. Harmless, since the sentence defers to the implementation.
