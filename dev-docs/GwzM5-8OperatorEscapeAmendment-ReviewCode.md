## Findings

### [P1-1] §7 item 2 omits the ActionJournal §2 cursor-derivation sentences that §3.3.2/§6.1 make mark-consuming — the amended contract would still forbid the amendment's own semantics, outside the controlling clause's reach

Amendment §3.3.2 (:905-907): "**Refined rule, normative:** cursor and prefix derivation **consume** disposition rows as retirement facts, exactly as they consume terminal participant rows and the durable-cursor markers." Amendment §6.1 (:1298-1300): "a strict precedence and a strict limit: durable fact → live proof → mark; and a mark retires a position for **cursor/prefix** purposes only."

Contradicting frozen text the §7 edit list never touches: `GwzM5-8I2ActionJournalContract.md` §2 :178-181 — "For rollback, owner/kind agreement includes the exact deterministic current cursor derived from durable participant terminal states, publication evidence, selected-root membership, and pending phase; a wrong or later owner is invalid at decode." — a closed input list with no mark arm, and it is *decode law* (journal-owner legality is computed from it). Likewise :185-188 — "an exact bound observation must also prove — by durable completion facts where present, and by exact bound live observation where absent — that every earlier position in the two-pass cursor is complete or currently unnecessary" — two arms, no mark arm; under it a marked earlier preservation position would demand exact live observation of a destroyed repository, which is precisely the wedge force-abandon exists to break. A marked participant deliberately has **no** terminal row (§2.3.2: "marked participants keep their last honest state"), so marks are representable in neither frozen input list.

Why this is P1 and not a text nit: the amendment's own authority clause (:18-20) says it is controlling "**and only for the clauses quoted verbatim in §1**". Neither sentence is quoted in §1.2 (which quotes :173-176 and :164-171 only), so after acceptance the un-amended ActionJournal sentences remain fully authoritative and flatly forbid the validator/dispatcher behavior §3.3.2 mandates — while TransitionDesign §6.7 *does* receive the mark-consumption rule (§7 item 3), creating a contract-vs-contract disagreement in the two documents that jointly own cursor legality.

Minimal remediation: quote both sentences in §1.2 and add to §7 item 2 two exact edits mirroring the §6.7 addition, e.g. ":178-181 gains '…, and a durable operator-override rollback-side mark retires that owner's remaining rollback positions for cursor purposes only'" and ":185-188 gains the third arm 'by the durable operator-override mark where one exists'", each with the exhaustion carve-out cross-reference.

### [P1-2] §7 item 5 omits ProtocolContract §1's context-legality sentence — after the mechanical edit, codes 62-65 are simultaneously required and forbidden to carry record context

Amendment §2.5.4 (:742-744): "All four require record context, carry absent member/detail/target fields, and take their `<reason>` from the registered lists …". §7 item 5 edits only "§1's error table appends codes 62-65 with the message bodies of §2.5.4 and the registered-reason requirement."

Contradicting frozen text: `GwzM5-8I2ProtocolContract.md` §1 :47-53 — "Codes 46/47 require applicable context; codes 49–61 require id and installed pair; … **Every other error forbids context. Codes 46–61 have absent member/detail/target fields.**" These sentences enumerate by code, not by table membership: with the table appended but the sentence untouched, 62-65 fall under "every other error forbids context", contradicting §2.5.4 — and this clause is fixture-enforced wire law (the parity/corpus suites pin which codes may carry `record_context`). As with [P1-1], the sentence is not quoted in §1.5, so the controlling clause does not arbitrate the contradiction.

Minimal remediation: add to §7 item 5 an exact edit of :47-53 — "codes 49–61" → "codes 49–65" in the require-and-absent-fields sentences (or an appended "codes 62–65 require id and installed pair" clause), keeping "every other error forbids context" true.

### [P1-3] The promised third status source cannot populate two REQUIRED wire fields for undecodable/future-envelope quarantined records — the class §3.1 explicitly supports

Amendment §3.1 (:808-810): "**No decode requirement.** Quarantine is byte-level so U7 records (unreadable, wrong-version, future-envelope) can be parked." §3.2.4 (:880-883): "`merge --status <id>` projects a quarantined record from quarantined bytes and the sidecar only …" — unconditional. §7 item 4's arbitration row: "quarantine present + open absent → quarantined projection" — unconditional. §8 item 10 pins "`source`/`archived`/`open` agreement across the three sources".

Contradicting wire reality: a status success is a `MergeResponse` whose field 3 `state` is a **required** `MergeOperationState` (`gwz.taut.py:1699`; `generated.rs:4869/:4883`), and the quarantined projection rides `MergeRecordProjection`, whose field 1 `source_version` is a **required** `MergeRecordVersion` with only `v0=0, v1=1` allocated (`gwz.taut.py:1164`; ProtocolContract §2 :89). For quarantined bytes that do not decode (or carry a future envelope), neither field is derivable; §2.5.2's `MergeQuarantineProjection.decoded_state` being optional degrades gracefully, but its required *containers* do not, and the frozen rendering rule "Human output never invents absent data" (ProtocolContract §4 :248) forbids synthesizing values. The amendment allocates no `unknown` discriminant, no optionality change (correctly — those would be non-append changes), and no alternative response shape, so package E3 cannot implement the promised surface without inventing wire semantics after the freeze.

Minimal remediation (pick one, in the amendment text): (a) specify that status of a quarantined record whose bytes do not decode as a supported record is a **typed error** (code 65, registered reason, sidecar echo in the message/`record_context`), with the quarantined *success* projection defined only for decodable bytes — and amend §7 item 4's arbitration rows plus §8 items 5/10 to match; or (b) define a sidecar-only response shape explicitly. Option (a) matches the existing posture (unreadable open records already surface as typed `MergeRecordUnreadable`, e.g. `status/snapshot.rs:177`).

### [P2-1] §1.2's annotation "an overridden abort clears the journal in the same write it writes `Aborted`" contradicts §2.3.2's own precondition
