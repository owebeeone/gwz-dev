## The two Safety fixes — CONFIRMED, in agreement with the docstring and the rule

**`impl`/`extern` blocks in a fn body are braced items again** (`target()` `:324-325`). In the first post-GO state the statement branch's `end(k, braces=True)` would have stepped over such a block and run into the next statement. Now: `fn f() { #[cfg(unix)] impl Trait for X {} go(); }` → `[]`; `#[cfg(unix)] unsafe impl Send for X {} #[cfg(unix)] go();` → only `go()`; `#[cfg(unix)] extern "C" { fn getpid() -> i32; } go(); … #[cfg(unix)] after();` → only `after()`. Unchanged around it: `extern crate alloc` in a body still flags, `extern "C" fn g() {}` passes and the bodiless `extern "C" fn h();` flags `fn h`; items inside a cfg-gated `impl` in a body are still scanned (`type T`, `delegate!(a)`); module-level `impl`/`extern` behave as before; `impl_helper();` and `externals();` are ordinary statements. The docstring's braced-item list (`:22-26`, "`impl`, … `extern { }`") already said this; the code now agrees wherever the block sits, which is the rule's "explicit enclosing boundary".

**`async { … }.await;` is an unbraced statement** (`BRACED_STATEMENTS` `:118-119`, docstring `:28-29`). `#[cfg(unix)] async { go().await }.await;` → `async{go().await}.await`; `async move { … }.await;` keyed likewise; `#[cfg(unix)] async { go().await };` → `async{go().await}`. Controls hold: `async fn g() {}` in a body passes as a braced item, `let h = async { 1 };` keys `let h`, a closure statement `|| { 1 };` is keyed, and `unsafe { }`, a labeled block, `const { 1 }`, a block and `loop` still pass. Basis for agreement: rustc's statement classification (`expr_requires_semi_to_be_stmt`) treats an async block like a closure, not like `if`/`match`/`loop`/`unsafe`/`const` blocks, so the statement carries a `;` outside its braces and they enclose nothing of the statement's boundary; the docstring states exactly that. I could not compile to re-prove the classification here (no cargo under the read-only rules), so that is a stated basis, not a run.
