## 1. Findings

### [P3-1] The frozen `ClientChannel::send(frame, lane)` makes the caller classify the lane that the amended contract says core classifies

- **Location:** `gwz-core/src/session_host/context.rs:314` (`pub fn send(&self, frame: Frame, lane: Lane)`); `gwz-core/docs/RustApi.md`, the new `ClientChannel` bullet ("A control call … goes on `Lane::Control` … every other call goes on `Lane::Call`", addressed to the caller); `dev-docs/GwzCoreSessionDesign.md` §3 as amended in this object ("Core classifies each frame's lane.") and §9 (`send(frame)`: "Core classifies the frame's lane (§3)"); crate map §3 ("classifying each outgoing frame's lane" is core's) and §5 ("lane classification in core"); step 4 plan §5 and §12, which record no deviation.
- **Root cause:** the plan's §5 froze the crate-level end's signature (`FrameSink::send(frame, lane)`) as gwz-core's public client end, and the contract amendment written the same day kept "core classifies", so the object contradicts itself on who decides the lane.
- **Violated invariant:** contract §3's guarantee that "the outstanding-call limit never refuses" control calls, and that "only a client that exceeds its own bounds meets a full call lane", is core's to keep; in this API it is kept only if every Rust driver passes the right lane.
- **Reproduction:** with `outstanding_calls = 1`, send one call on `Lane::Call`, then an `operation.cancel` frame on `Lane::Call`: `SendError::Full` comes back and the cancel never reaches the host. Core made no classification, and nothing in core could have, since decoding the header is CS1.6's.
- **Impact:** a frozen public signature and its documentation assign to drivers a decision the contract, the map and `RustApi.md`'s own prose assign to core; a later lane-less `send(frame)` would be a second frozen entry point.
- **Required correction (text, bounded):** record the deviation where the step 4 plan's §12 and the contract's 2026-09-29 status bullet record the others: the in-process client end takes the lane its caller classified, "core classifies" holds for the extension's `send(frame)` (§9) and for the host's replies, and gwz-cli (the Rust driver) classifies as the extension does. Alternatively, plan a `send(frame)` on `ClientChannel` for CS1.6, when the registry lets core classify, and state that `send(frame, lane)` is the pre-CS1.6 end.
- **Closure:** the plan's §12 and the contract's status bullet name the deviation; if the code route is taken, a core test that an `operation.cancel` frame sent through `ClientChannel::send(frame)` goes on the control lane while the call lane is full.
