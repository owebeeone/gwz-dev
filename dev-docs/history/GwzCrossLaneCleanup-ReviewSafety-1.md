### S-7 (P3) — The `InvalidRequest` drop is wider than its comment, so a driver bug could be swallowed instead of closing the session

- **Location:** `gwz-core/src/transport_host/session/driver.rs:473-484` (drop arm) and the comment "for this session's request, `send` answers InvalidRequest only for a route it no longer has; its other rejections are Protocol"; gwz-transport `src/mux/mod.rs:375-392` (`send`), read-only.
- **Root cause:** `send` answers `InvalidRequest` for (a) no route for `stream_id` (`:380`), and (b) `route.request != request || session_id != self.session || version != 2` (`:382`). The driver's guard removes only the session-id case; a message routed under another request id, or with a version other than 2, is also dropped silently now. `validate_transition`, `validate_opened`, `admit_limited` and `enqueue`'s charge answer `Protocol`, and `live()` answers `Closed`, so those still close the session; `enqueue`'s identifier check is `InvalidRequest` but on the request id the driver itself supplies.
- **Violated invariant:** a fix for a race should drop exactly the stale case.
- **Reproduction:** by construction only: the pump builds each message from the stream's own endpoint under `entry.request`, and the mux allocates stream ids monotonically, so (b) needs a driver defect. A message for a wrongly attributed request would be dropped rather than failing loudly.
- **Impact:** bounded to masking a future defect in the driver's own bookkeeping, where the stream would then stall rather than the session closing; users see no change today. The sealed-request skip (`:467`) is sound: after `seal` the mux owns the request's cancellation (`ClientRequest::drop` cancels, then seals), and the `take()` discards the message so the terminal still retires the entry.
- **Required correction:** narrow the arm to the retired-route case — check the route's absence (e.g. `!owner.has_route(stream_id)`, or match on the stream's own terminal being queued) — or at least assert `message.version == 2` and the entry's request before dropping, and fix the comment.
- **Closure test:** `fault_tests::a_client_message_queued_before_the_endpoints_terminal_never_closes_the_session` still passes, and a new fixture sending a version-1 envelope for a live route closes the session.

## 3. The round-2 changes on this axis

No panic: a scratch crate (`…/safety/turns-fuzz/main.rs`, `rustc` only, a two-variant `GitService` stub) fed 400,000 exchanges of random bytes, protocol vocabulary, oversized lines and arbitrary chunking through `client_bytes`/`server_bytes`/`server_stderr`/`client_end` with no panic; `git_turns_tests` (13) and `ssh_pump_clock_tests` (3) pass in the prepared candidate. Unknown stays `Network`: every unrecognised line, out-of-turn server output, `no-done`, a bare ACK before `done`, protocol v2, an `ERR` advertisement, stderr during the client's turn, the client's half-close and a push's first byte call `stop()`, after which `clients_turn()` is false for good. **Can a server hold the clock at `Idle` while it owes bytes?** No path found: `Idle` needs `forward` and `reverse` empty *and* `clients_turn()`, which needs the advertisement's flush, a rested client, `naks == rounds` and no unlisted deepen; a flushed round without its NAK, anything after `done`, a partial packet (`at_boundary()` false) and an extra NAK all stay `Network`. A server that finishes its turn and then dies silently is the one case that sits `Idle`: the pump then sends the reverse end on stdout/stderr EOF (`ssh_pump.rs:320`), so the client reads EOF, and its next write surfaces the dead channel; a death with stderr output during the client's turn stops the tracker and the 3 s clock runs.
