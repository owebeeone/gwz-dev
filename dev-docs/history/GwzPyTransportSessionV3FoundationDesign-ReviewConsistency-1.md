## 1. Findings

### R2-C-P2-1 — The exact V2 supersession list omits the accepted-worker finish exception

**Location and invariant.** Accepted [V2 §5](/Users/owebeeone/limbo/gwz-dev/dev-docs/GwzPyTransportSessionV2Design.md:37) says a worker panic after `Accepted» publishes its attributed terminal result **after** `TransportRequest.finish()». V3 says `finish()» itself may panic, or the accepted owner may be lost outside the handler catch; in either case `AcceptedOperation::Drop» publishes `Failed» with unconfirmed cleanup ([§5.2](/Users/owebeeone/limbo/gwz-dev/dev-docs/GwzPyTransportSessionV3FoundationDesign.md:99), [§7.2](/Users/owebeeone/limbo/gwz-dev/dev-docs/GwzPyTransportSessionV3FoundationDesign.md:203), [§7.3](/Users/owebeeone/limbo/gwz-dev/dev-docs/GwzPyTransportSessionV3FoundationDesign.md:207)). V3 [§10](/Users/owebeeone/limbo/gwz-dev/dev-docs/GwzPyTransportSessionV3FoundationDesign.md:240) claims exactly four V2 amendments, with item 4 superseding **only** the spawn-and-gate wording for `call()» and [line 247](/Users/owebeeone/limbo/gwz-dev/dev-docs/GwzPyTransportSessionV3FoundationDesign.md:247) preserving everything else.

**Reproduction and impact.** Inject the `finish()» panic already required by [§12.3](/Users/owebeeone/limbo/gwz-dev/dev-docs/GwzPyTransportSessionV3FoundationDesign.md:299). An implementation following V3 must settle through Drop without a returned `finish()» report, while one following the still-accepted V2 §5 cannot publish yet. The two controlling contracts give incompatible terminal-publication rules for the same tested fault. The fallback is sensible, but a release or implementation reviewer cannot certify both contracts as written.

**Remedy and closure test.** Add an exact V2 §5 supersession for finish unwind or lost accepted-owner fallback, stating the conservative terminal and cleanup guarantee and its limit; keep the normal and caught-handler-panic finish-first rule. In the focused test, make `finish()» panic and verify one failed terminal with unconfirmed cleanup, then hold a catchable handler panic in `finish()» and verify no terminal publishes until `finish()» returns.

### R2-C-P2-2 — The required timeout matrix promises retry after an install timeout that closes the generation

**Location and invariant.** V3 says dropping or failing phase 1 after pool mutation invokes `CapacityMutation» and closes the endpoint generation ([§6](/Users/owebeeone/limbo/gwz-dev/dev-docs/GwzPyTransportSessionV3FoundationDesign.md:152)); the [core guard](/Users/owebeeone/limbo/gwz-dev/gwz-core/src/transport_host/session.rs:240) closes when armed, and an install can time out while that guard is armed during retirement ([lines 622–667](/Users/owebeeone/limbo/gwz-dev/gwz-core/src/transport_host/session.rs:622)). V3 correctly qualifies the cancellation case as retryable only while the generation remains open ([§11](/Users/owebeeone/limbo/gwz-dev/dev-docs/GwzPyTransportSessionV3FoundationDesign.md:273)). But the same matrix labels **“Capacity leadership or install timeout”** unconditionally retryable “yes” in its “Retry same ID in this generation” column ([line 266](/Users/owebeeone/limbo/gwz-dev/dev-docs/GwzPyTransportSessionV3FoundationDesign.md:266)). [§12.2](/Users/owebeeone/limbo/gwz-dev/dev-docs/GwzPyTransportSessionV3FoundationDesign.md:298) makes matrix rows required closure cases.

**Reproduction and impact.** Force capacity retirement to remain pending until its arrival deadline after capacity mutation. The armed guard closes the generation and phase 1 returns a nonconsumed refusal. The same ID has not been registered, but no new handle can admit it **in that generation**. The required matrix assertion is therefore unsatisfiable without weakening the fail-closed rule; it can also teach implementers or callers a false recovery action.

**Remedy and closure test.** Split leadership/pre-mutation timeout from post-mutation install timeout, or qualify the retry column by generation state as in line 273. A focused test should hold retirement past the deadline, assert `request_id_consumed == false», assert the generation is closed, and assert same-generation admission refuses; separately test a pre-mutation leadership timeout that permits retry after contention clears.

## 2. Invariant analysis

The prior inline-`call()» and legacy-core counterexamples no longer refute the candidate. V3 gives `submit()» a parked gate, gives inline `call()» an explicit V2 exception, and leaves the legacy CLI/local `request()» route and timing intact. Normal phase-2 returns use `Refused», `Consumed», or `Ready»; a mux-registration unwind uses `MayHaveRegistered» and closes rather than inventing retryability. The Python guide now explains that nonconsumption alone does not reopen a closed generation. The close-summary reservation and session-then-record lock order are stated consistently across the transition and reader sections.

The remaining contradictions are precise. The finish-unwind fallback needs to be part of the declared V2 supersession, and the install-timeout matrix needs to distinguish nonconsumption from same-generation availability. Deferred ledger, rollover, transport stress, platform, and wheel outcomes were not treated as reasons to leave either contract shape ambiguous.
