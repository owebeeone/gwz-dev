## Bounded redesign proposal for the operator decision

Recommend **redesign**, not acceptance of the known retry and terminality defects. The narrow replacement boundary would make core's request registration provenance explicit in an internal Rust admission result. A failure before registration must carry `not_registered`; after the lifetime ID is inserted it must carry `registered`, regardless of its error code. Python would update its request-ID mapping from that provenance, not infer it from `ModelError.code` or display text. This need not change the existing Taut method set or the `gwz-transport` message envelope.

The same redesign should centralize settlement of an issued Python operation ID across every exit between reservation and `Accepted`: argument decoding, current-directory capture, session/endpoint construction, admission, pre-spawn validation, spawn failure and cancellation. It should retain a typed pre-effect refusal before waking any waiter and prevent a worker's generic failure recorder from replacing that refusal. Post-registration failures retain the consumed request ID and conservative effect attribution. A new bounded design object should enumerate those state transitions and be reviewed before implementation restarts. Its closure tests must distinguish pre- and post-registration `IoError` without parsing text, and prove that both `call()` and `submit()` terminate the issued record on every pre-worker exit.

Accepting the current foundation would knowingly waive the same-ID retry guarantee after a capacity timeout and allow result waiters to hang or see an inconsistent error. No such waiver has been given. The full byte ledger, timer, public handles, rollover, transport stress and platform gates remain unfinished regardless of this decision.
