## Nonblocking findings folded into the same patch

| Finding | Disposition | Closure evidence |
| --- | --- | --- |
| **Receipt before admission** — Consistency P3-14, Safety P3-7 | **Creation:** the thread that reads the channel creates each call's pending record at receipt: its `call_id` key, its token, its gate and, for an operation method, its `operation_id`. This happens before any resolution, so O7's "at admission" becomes "at receipt". **Admission:** resolution and the class decision then run on the admission thread in receipt order, and a resolution failure settles the record with its refusal, before any effect. **Control frames and reads** are handled at once on the reading thread and never wait behind admission. A cancel naming a pending call cancels its token; admission then settles the call `Cancelled` before any effect. **Close** settles every pending call `Cancelled` and does not wait for an admission thread stuck in resolution beyond the close bound. §16 states the remaining cost: a hung resolution delays later admissions, but never control frames or reads. | With resolution latched for one submit, a cancel of that submit settles it `Cancelled` and its handler never runs. A cancel of another, running operation and a close both complete within their own bounds. |
| **`call_id` monotonicity** — Consistency P3-18, Safety P3-13 | A `SessionCall` whose `call_id` is not greater than the highest `call_id` received in the session is a protocol error (§3). This covers reusing an outstanding ID and replaces the narrower rule. The bridge already allocates and sends under one lock. | A stream-bridge test sends a non-increasing ID and the session ends. |
| **Host context scope** — Consistency P3-21, Safety P3-6 | **Contents:** the SSH setup supervisor with its helper and cleanup budgets, the HTTPS helper slots, the member lock manager (moved from the session context) and a registry of detached workers. **Surface:** the extension gains a fifth entry point, a host-context constructor, and §9 lists it. **Default:** drivers create one host context and pass it to every session they open. gwz-cli creates one at startup. The Python bridge creates one per process on first use and passes it to every session; `NativeCoreBridge` also accepts one to share, and `Client` is unchanged. **Detached workers:** a session sharing the host context treats a detached worker's workspace or member as busy, so a later W on that workspace, or an N step on that member, waits in the queue until the worker ends. **Drop:** the host context's drop stops its reaper thread once its jobs finish. **§14:** the SSH agent design's process-wide scope and single control loop become per-host-context. With the default of one per driver process, its cap and single loop hold per process as before. **§5.1:** the attribution becomes "another process, a session with another host context, or a detached worker, which the refusal names when the host context knows it". | After a close with a latched W worker, a new session sharing the host context submits a W on the same workspace: it queues until the latch is released. Two Clients in one process share the SSH helper budget. A session without the shared host context gets a refusal that names the lock's possible holders, never only "another process". |
| **`diff.output` release** — Consistency P3-15 | Define "open" and adopt taut-shape's release rule for both log kinds. A log is released when its producer has sealed or closed it and its last reader stream has ended, through the existing `DiffLogRegistry::release`. Session end is the backstop. `log.output`'s rule that end stream releases the log stays as the stated special case. End stream on `events.subscribe` ends that reader's stream and releases nothing. | 65 sequential diffs read to EOF on one session succeed. With 64 diffs' streams left open the next is refused, and ending those streams admits it. |
| **Log appends through the gate** — Consistency P3-16 | Log appends, seal and close are gated. After cancellation the gate refuses further appends with `Cancelled`, so the producer stops. After revocation it drops them. The spool is written only by the registry through the gate; a producer never holds the spool's file handle. Close step 7 can then delete spools safely. | A `log` producer detached at the close bound and released afterwards writes nothing to the spool path, and the registry holds no entry for it. |
| **Reply kind** — Consistency P3-17 | **Errors:** a unary or direct call whose record ends `Cancelled`, or `Failed` without a response, receives a `SessionError` carrying the terminal's first `GwzError` and its `ResponseMeta`. **Responses:** a handler that produced a response, even with a failed aggregate status, gets a `SessionReply`. **Waiting direct calls:** `operation.cancel` on a direct call still waiting for a worker settles it `Cancelled` before it runs. | Cancelling a queued unary call, and a waiting direct call, yields `SessionError{cancelled}` for both, on both bridges. |
| **O9's wording** — Consistency P3-19 | Reword O9, the GWZDesign paragraph and the GWZRequirements bullet: "no process-global mutable state other than the inventoried `permanent` entries, which carry no session-relevant state or are imposed by a dependency (libgit2's server timeout in ordinary builds)". | Documentary: each `permanent` allowlist entry states its reason, as all eleven do today. |
| **O7's scope** — Consistency P3-20 | **O7:** state it as the operator gave it: any threaded or async API in core and the extension. **Legacy handle:** mark `TransportRequest::cancellation_handle()` and the legacy `TransportSession` entry points deprecated. Their removal is tied to gwz-cli's and gwz-py's move onto the session (proposals §9, phases 3 and 5). **Requirements:** align the GWZRequirements bullet. | Documentary now; a deprecation test at implementation. |
| **`operation.result` body** — Consistency P3-22 | Over the session, `operation.result`'s scalar `operation_id` travels in an appended `OperationResultRequest { operation_id: str (1) }`, as the first plan said. The new methods' requests are defined the same way: `OperationResponseRequest`, `OperationCancelRequest` (a `call_id` or an `operation_id`), `OperationReleaseRequest` and `SessionCloseRequest`. | A codec round trip of each call body on both language projections. |
| **Delivered once** — Safety P3-8 | **Delivery:** a record counts as delivered only when every view its method declares has been delivered (the result, and for a merge the response too), or when it is released. **Bridge copy:** a result reply that arrives after its waiter was cancelled is kept in the bridge's view for that operation until release, instead of being dropped. **Stream helpers:** the Client's stream helpers deliver the result, or release the record, in `finally`. | A merge handle's result under a full table still returns its response. A cancelled result wait followed by a retry returns the result. 200 streams exited early do not exhaust admission. |
| **Detached marker** — Safety P3-9 | A detached operation's `OperationResult` carries a second `errors` entry after `cancelled`: `internal_error`, "detached at the close bound; outcome unknown". Update the `cancelled` (73) schema comment and the ErrorCatalog: `cancelled` covers cancels before effect as well as after. | §15.9's latch test reads the detached operation's result and finds the marker. |
| **Snapshot handling** — Safety P3-10 | **Secret:** the environment snapshot is secret-bearing. It is never serialized into a frame, event, result, error message or log, and it goes only to the processes that need it (P3-11). **Lifetime:** it is dropped when the session ends. **Capture:** it is captured losslessly, with `os.environb` on POSIX and `os.environ` on Windows. **Wire proof:** `StreamCoreBridge` starts the host binary with the snapshot it would pass to `open`, so the two runs see the same environment. **Scope:** the snapshot fixes environment values and paths, not the contents of the files they name, such as `GIT_SSL_CAINFO`. | An error raised for an invalid proxy or CA setting contains no environment value. The snapshot is unreachable after close. |
| **Child processes** — Safety P3-11 | Session-path child processes are spawned with `env_clear()` plus the snapshot, as `gh` already is. That covers `git tag`, `git commit` and the local-import `git fetch` fallback. The check gains a `process` kind that flags every production `Command::new`. Existing spawns are listed as `debt` when they inherit the live environment, and `permanent` when they already use `env_clear`. | After `open`, changing `GIT_CONFIG_GLOBAL` leaves a later `commit`'s committer identity unchanged. A new unlisted `Command::new` fails the check. |
| **gwz-transport coverage** — Safety P3-12 | **Allowlist:** gwz-transport gets its own allowlist (`scripts/process_globals_allowlist.json`, root `src/lib.rs`). **Test:** it also gets a unittest in `scripts/` that its CI's unittest discovery already runs. That test runs gwz-core's checker from a gwz-core checkout beside it, as gwz-py's test does, and the contracts workflow gains that checkout. **§5.7** names the three covered repositories. | A fault-injected static in gwz-transport fails its test run. |

## Residual risks adopted

- **Member rows (§6):** a handler that can fail late reports member rows from its own state, not only the planned rows marked skipped.
- **Transport builds:** `git://`, `http://` and `file://` remotes still use libgit2's native transports and its process-wide timeout. §5.6 and §5.8 say so.
- **Limits:** `open` validates the limits it is given, so the table holds at least the running plus the queued operations.
- **Host binary:** the development-only host binary is a Cargo example target, so no published crate installs it.
- **Lock waits:** a member-lock wait already in progress wakes on cancellation, because it is a gate crossing.
- **Keeping in step:** the build-dependent statements in §4.2, §5.3, §5.8, §13 and §15.15 stay aligned whenever either build changes.
