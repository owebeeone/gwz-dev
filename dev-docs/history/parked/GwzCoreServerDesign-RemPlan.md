# GWZ core server design, revision 1 (TR1.3) — first remediation plan

Date: 2026-09-28. Status: **remediation plan for [the first verdict](GwzCoreServerDesign-Verdict.md); applied as revision 2 of `GwzCoreServerDesign.md`, in one patch.**

Every finding of the three reports gets exactly one disposition: [Consistency](GwzCoreServerDesign-ReviewConsistency.md) C-P3-1 to C-P3-11, [Safety](GwzCoreServerDesign-ReviewSafety.md) S-P1-1, S-P2-1 to S-P2-3 and S-P3-1 to S-P3-13, and [Surface](GwzCoreServerDesign-ReviewSurface.md) Su-P2-1, Su-P2-2 and Su-P3-1 to Su-P3-13.
- All findings are accepted. None is disputed.
- Every correction is to the design's text. None changes the trust boundary, the must-match model or the reuse model.
- Where a reviewer left a choice open, the choice is stated. Three change something a reviewer attacked in round 1, and the re-verdict must check each against the old counterexamples:
  - the Linux sandbox rule becomes absolute again (S-P2-1, C-P3-1);
  - the handshake gains a secret-free identity frame the server sends first (S-P2-2, with S-P3-1, S-P3-5 and S-P3-13);
  - the `server` command's actions become subcommands (Su-P2-2).
- Two corrections reach accepted text outside the design, and the design's "On GO" list carries them with exact replacement text: the release plan's Phase 10 post-release check (the subcommand spelling), and the reuse design's §11 composition note (C-P3-7).
- The revision also takes the reviewers' residual notes where they are cheap (§4).

## 1. Blocking findings

| ID | Disposition | Where | Closure test |
| --- | --- | --- | --- |
| S-P1-1 | Every file the host creates or opens in the per-user directory or at `--log PATH` (the lock, the log, and the files the OpenSSL scan reads) is opened relative to the walked directory's descriptor with no-follow and close-on-exec, and non-blocking during the open. An existing entry is used only if it is a regular file the user owns with no group or other permission bits. A new file is created 0600. The log is only ever appended, never truncated. An entry that fails these checks is reported, never followed, truncated or written, and the start refuses. The stale-socket check and removal use no-follow stat and unlink on the same directory descriptor. The OpenSSL scan also reads regular files only, with a size bound. On Windows, opens use `FILE_FLAG_OPEN_REPARSE_POINT`, a reparse point is refused, and the owner is checked. | §4, §5 (scan), §6, §11, §12 | Linux and macOS socket-host rows: a symbolic link, and separately a FIFO, planted at the log and at the lock before `server start`, and a link named by `--log`. The start refuses within a bound, and the link's target is unchanged in size and hash. Windows: a junction and a symbolic link at the log path are refused. |
| S-P2-1, C-P3-1 | **Choice: the Linux rule is absolute again.** The relative rule is withdrawn, with its three claims. On Linux a process is sandboxed when its `Seccomp` status is not 0, or when its user namespace is not the initial one, and a peer in a different mount or user namespace from the checker is refused. Mark the detection of the initial user namespace as inferred, with a test. Every sandboxed caller is then refused on all three platforms before any connect or start, with a message naming the cause and `--no-server`. The client checks itself first, and `server start` refuses inside a detectable sandbox. This answers the plan's TR1.3 "Defaults" bullet as written, so §18 records no departure. §14 states the consequence: in this release there is no server inside a container that applies a seccomp profile, Docker's default included, and such a user runs in-process. §14 also keeps Landlock-only sandboxes and kernels before 5.9 as the disclosed residual, in one place. | §4, §7, §11, §12, §14, §18 | Linux rows: two seccomp-only sandboxes of equal filter count in one namespace, each refused as client and as listener; a caller inside `unshare -U` or bubblewrap is refused before any connect, and no server starts. On all three platforms, a sandboxed caller with `GWZ_SERVER` set gets the refusal naming the cause and `--no-server`, at the `auto` path and at an explicit address. |
| S-P2-2 | **Choice: a secret-free identity frame.** After its peer check, the host sends `SessionHello` first: protocol range, product, core version and build, and process ID. It uses a new frame tag, appended. The client verifies the listener, then waits a bounded time for a well-formed `SessionHello`: 30 seconds, and 5 seconds for `server status` and `server stop`. Only then does it send `SessionOpen`. At the bound, the client disconnects and fails with `server_unavailable`, naming the listener's process ID (from the kernel), the lock path and the log path. The same frame opens every byte stream: socket, stdio, the SSH remote form and the contract's test host. | §3, §8, §9, §12, §15, §16, §17 | A host double that accepts, passes the peer check and never answers: a client command, `server status` and `server stop` each fail within their bound, naming the double's process ID; no frame follows the connect. |
| S-P2-3 | Before removing an existing socket file, the host connects to it and sends nothing. Refusal of the connection (no listener) shows the socket is stale, and it is removed. A connection that succeeds, or any other error, refuses the start with `server_unavailable`, naming the address and the listening process ID from the peer credentials. The `.lock` is created only after the walk and the directory checks pass. The sentence becomes: "a mistyped address never deletes a file, and never a socket something still answers on". | §4, §11, §12 | A test daemon listening on a user-owned socket at an explicit address: `server start` refuses, and the daemon's socket survives and still answers. A socket file with no listener is removed and the start proceeds. |
| Su-P2-1 | `--ssh-timeout` has one default, 9 seconds, in every role: the client, `server start`, `server stdio`, and both CLIs. The retry plan changes it from 1.0.17's 3 seconds (its default table, and its help text for `--ssh-timeout`), and S7.2's migration notes say so; §17 cites both. 0 means no timeout, is legal for the server as for the client, and must match like any other value. With both defaults equal, a client and server that keep their defaults never meet the timeout refusal. | §5, §6, §17 | A server started with no options and a client with no options: a native-path operation is not refused. Help-text rows assert the same default in both CLIs. |
| Su-P2-2 | **Choice: subcommands.** The spelling becomes `gwz server start [--foreground] [--max-sessions N] [--idle-exit DURATION] [--log PATH]`, `gwz server stop [--force]`, `gwz server status`, `gwz server list` (Su-P3-5) and `gwz server stdio`, each with a one-line summary. The same verbs and options apply in gwz-py. The address rule applies to `start`, `stop` and `status` (C-P3-5). Bare `gwz server` prints the verb list, as `gwz local` does. Each action takes only its own options. The top-level help gains a line for the family (Su-P3-3). The client forms stay global options: `--server auto|stdio|ADDRESS` and `--no-server`. The amendment's working name `server --stdio` becomes `server stdio`, which amendment §5 delegates to TR1.3. The release plan's Phase 10 post-release check line ("`server --start`, `--status` and `--stop` from each installed CLI") gets exact replacement text in the "On GO" list. The design uses the new spelling everywhere. The Surface reviewer's alternative, keeping flags with a recorded deviation, is not taken. | §6, §8, §15, §16, §17, all spellings | `gwz server` with no verb prints the verbs; `gwz --help` lists the family; each action refuses another action's options; gwz-py matches. |

## 3. Nonblocking findings, Safety

| ID | Disposition | Where | Closure test |
| --- | --- | --- | --- |
| S-P3-1 | Resolved by S-P2-2's identity frame: the snapshot crosses only after a well-formed `SessionHello`, so a same-user program that does not speak the protocol receives no environment byte. §4's statement about disclosure is corrected accordingly. | §3, §4 | An echo double and a silent double at an explicit address receive no environment bytes. |
| S-P3-2 | The lock holder writes its process ID into the lock file once it holds the lock, under S-P1-1's open rule. A starter that finds the lock held reads it and names the process ID and the log path. On Windows the same. | §4, §11 | A second `server start` while a server runs exits 1 naming its process ID; with the holder gone and the lock free, the start proceeds. |
| S-P3-3 | A channel that closes before the identity frame or before `SessionOpened` is reported as `server_unavailable`, never `server_session_closed`, since nothing reached core; under `auto` the client may then start a server once. Shutdown keeps its order, because releasing the address before the drain would let a second server run beside the draining one's detached workers. The drafter checks whether the file-system workspace lock would make an early release safe, and states the reason either way. | §6, §7, §17 | A client arriving during a drain gets `server_unavailable`, never `server_session_closed`; the old process exits within its bound. |
| S-P3-4 | A started copy and the stdio child close every descriptor above 2 before serving, or the starter marks them close-on-exec; on Windows only the log handle, or the stdio pipes, are passed, through an explicit handle list. | §6, §11, §15 | A starter holding an `flock`ed descriptor and a pipe's write end: after `server start` returns, another process can take the lock, and the pipe's reader sees end of file. |
| S-P3-5 | At an explicit address, a `SessionHello` whose core version or build differs from the client's is refused with `server_version_mismatch` before the snapshot crosses. | §3, §14, §17 | A client and a server double of different core versions at an explicit address: refused, and no environment bytes sent. |
| S-P3-6 | On Windows the client requires the listener's integrity level to equal its own, and refuses otherwise with `server_listener_refused`. | §4, §11, §12 | dabeest: an elevated client against a medium server is refused before any frame; a medium client against an elevated server is refused by the server. |
| S-P3-7 | The Windows `auto` pipe name gains a per-user secret: random, created once in the per-user directory under its user-only ACL, and read by both CLIs; creation that finds the file already present reads it. The drafter may instead state the residual, with the explicit-address workaround, if the secret file cannot be made race-free; either way §14 says which. | §4, §11, §14 | Windows CI: a pipe that another user pre-creates under a guessed name does not stop the victim's `auto` server. |
| S-P3-8 | An agent pipe refused by the local-only rule gets a named code and message. | S-P3-9 | A client whose OpenSSL scan cannot finish refuses `auto` with `server_unavailable` naming the file and the reason, and starts nothing. | S-P3-10 | A socket or stdio host refuses at open, with `server_environment_mismatch` naming the variable, any must-match value that is a relative path, and a set-but-empty `XDG_CONFIG_HOME`. | §5, §12 | An empty `XDG_CONFIG_HOME` and a relative `OPENSSL_CONF` are refused at open over a socket and in the stdio form; absolute values pass. |

## 5. Residual notes taken

- **Safety:**
  - a server that detects a changed OpenSSL file exits at its next idle point, so a service manager restarts it;
  - §14 names a fallback if `GetNamedPipeServerProcessId` fails on client handles, and listener verification fails closed until then.
- **Surface:**
  - the `hook` family always runs in-process and never reads `GWZ_SERVER`, because it runs inside tool sandboxes, which the server refuses;
  - §17 states which spelling gwz-py accepts for the global options around `server`;
  - `--jsonl` gives the same records as `--json`, and `--dry-run` is refused on `server`;
  - the log is size-bounded, with one previous file kept;
  - the `server start` message adds how to use the server ("use it with --server auto or GWZ_SERVER=auto").
- **Consistency:**
  - "Both directions are idempotent" is qualified for `start --foreground` on a held lock;
  - `server_unavailable`'s 30-second "When" carries the handshake's scope.

Not taken, outside the object:
- `gwz help` with a two-word topic does not resolve today. That is gwz-cli's help verb, and is recorded for the program.
- The session plan calls gwz-py's console script `gwz`, which is TR1.4b's to correct.

## 6. Re-review

- The same three reviewers give a focused re-verdict on revision 2's SHA-256. Each gets this plan and the diff from revision 1, and covers both its own findings and every changed range.
- The three choices marked in the introduction change what round 1 attacked. Each reviewer re-runs its round-1 counterexamples against them and labels any new root cause it finds there as architectural or not. The two-round cap turns on that label.
- Acceptance needs GO from all three axes on revision 2, or, for a finding confined to §16, the operator's acceptance of the rest without §16.
- A new architectural root cause stops the lane for the operator.
