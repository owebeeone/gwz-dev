## 2. Invariant analysis

Attacks that failed, with the evidence that defeated them.

1. **Transport prefix ordering, all forms.** For every string the port can hand libgit2 (`file:///` + canonical absolute path), `transport_find_by_url` returns the local transport at row 4 before any heuristic; custom transports (`custom_transports`, searched first) are empty in this process. **Held.**
2. **Percent-encoding round trip.** `Url::from_file_path` encodes only `%`, space, `"#<>?`\{\}` and control/non-ASCII bytes; `git__percent_decode` restores every `%XX`; `:` is never encoded. A canonical path containing `%`, spaces or non-UTF-8 bytes therefore reopens exactly; the `:` case is the executed sample. **Held.**
3. **Input refusals unchanged.** `://`, `git@`, `ssh@`, missing directory, empty refspecs/refspec all refuse before `open_repo`; `file:///tmp/anything` remains refused. **Held.**
4. **No credential or network helper became reachable.** Fetch attaches no `RemoteCallbacks`; push attaches only `push_update_reference`; the `ssh` feature is still compiled in but the SSH row is unreachable for a `file://` string. `url.<base>.insteadOf` rewriting (`remote.c:254`, applied at remote creation for anonymous remotes too) applies equally to the old bare-path form and is the user's own configuration; with no callbacks a rewrite to a network transport fails closed. **Held** (pre-existing, not a regression).
5. **Canonicalisation side effects.** `canonicalize` resolves symlinks (a member behind a symlink opens at its real path; results still name the caller's path) and never yields a relative path, so the `from_file_path` error arm is unreachable in practice; a canonicalise I/O failure refuses `invalid_request` before any effect. **Held.**
6. **FETCH_HEAD chain.** `git_remote_fetch` → `git_remote_update_tips` → unconditional `truncate_fetch_head` (`O_CREAT|O_TRUNC`) → per-spec record write gated by `UPDATE_FETCHHEAD` (cleared). Both measured arms follow; a libgit2 change in either direction fails one of the two assertions. **Held.**
7. **Engine gate identity.** `validate_merge_start_shape` *is* `validate_merge_request` for `Start`; `merge_start_shape_is_the_engine_start_gate_and_start_only` asserts code and message equality for five malformed shapes and the `Start`-only refusal for the four other ops; `validate_merge_request` itself is byte-unchanged. The projection replaces the user's `source_ref` with the placeholder, which is correct: the delegated request at step 6 carries the import ref, and the user's `source_ref` is consumed by the import step (`SourceSelector`), which fails before the engine if it does not resolve. **Held.**
8. **Refusal order.** Wrapper: attribution → selector/op/`merge_id`/`preserve`/empty-`source_ref` → engine gate → dry-run → workspace → store observation (`family_merge.rs:60-67`); the engine's own dry-run rule is non-Start only, so the gate cannot pre-empt the wrapper's `unsupported_operation` for a well-formed dry run. **Held.**
