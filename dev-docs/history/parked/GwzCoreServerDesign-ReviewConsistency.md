## 1. Findings (one subsection per finding, severity-ordered)

### P3-1. The sandboxed-caller rule is stated two ways in one paragraph, and the Phase 7 exit row that tests it is unsatisfiable as written on Linux

- **Location.** Object line 537 (§7 "Sandboxed callers"), sentence 1 against sentence 3; object line 249 (§4 "Sandboxed callers", Linux); object line 792 (§12 gwz-cli, "a sandboxed caller with `GWZ_SERVER` set gets a refusal … (Phase 7 exit)"); object line 1166 (§18 "Defaults" row). Controlling text: frozen plan line 236 (TR1.3 "Defaults": "It says what a sandboxed caller with `GWZ_SERVER` set sees: a refusal that names the cause and `--no-server`") and line 376 (the Phase 7 exit row, unconditional).
- **Root cause.** The object's Linux sandbox rule is relative (§4 line 228: a peer is refused only when its namespaces or seccomp filter count differ from the checking process's; line 249: the rule "needs a peer"). Under it, `--server auto` from inside a Linux sandbox with no server outside starts a server inside the sandbox and is served (line 537, sentence 3). Sentence 1 of the same paragraph, the §12 row and the plan's bullet say every sandboxed caller with `GWZ_SERVER` set gets a refusal.
- **Invariant violated.** One rule per clause; a verification row must be runnable as written; the object must answer a TR1.3 clause with the same rule or record the departure.
- **Reproduction.** Linux; `unshare -U -r` (or bubblewrap) with `$XDG_RUNTIME_DIR` writable; no gwz server outside; `GWZ_SERVER=auto gwz status`. By §4 and §7 sentence 3, a server starts inside the namespace and answers. By §7 sentence 1, the §12 row and the plan bullet, a refusal naming the cause and `--no-server` is expected.
- **Impact.** The Phase 7 exit row cannot pass on Linux for the `auto`/no-outside-server case, or its test silently picks the one scenario that refuses (an outside server exists), and the plan's bullet is answered with a different rule without a record of the difference.
- **Required correction.** In §7 (and §4), state the rule per platform: on macOS and Windows every sandboxed caller with `GWZ_SERVER` set is refused before any connection or start; on Linux the refusal comes from the peer check of a server outside the sandbox, and `--server auto` with no such server starts a server inside the sandbox that serves only that sandbox. Pin the §12 row's scenario: a server started outside the sandbox, at the `auto` path and at an explicit address, on all three platforms; plus the Linux `auto`/no-outside-server row with its expected outcome. Record the Linux departure from the plan bullet in the §18 "Defaults" row.
- **Closure test.** The pinned §12 rows: the refusal naming the cause and `--no-server` against an outside server on each platform; on Linux, `auto` inside `unshare` with no outside server serves, and its socket refuses a client from outside the namespace.

### P3-2. The `auto` key's "identities of the files" does not match the triple "Files read once" records, so an in-place edit contradicts "a changed configuration gets a new server"

- **Location.** Object line 207 (§4 key: "the identities of the files that scan read and, on Linux, of the CA bundle") and line 385 (§5 "The key": "the identities of the files … A changed configuration or bundle therefore gets a new server under `auto`") against line 382 (§5 "Files read once": "records the identity, size and modification time of each file").
- **Root cause.** "Identity" is used for a triple in one bullet and for one of its three members in the other two.
- **Invariant violated.** One definition per term; §5's and §14's claim that under `auto` no `server_environment_mismatch` arises for OpenSSL's files (lines 411, 862).
- **Reproduction.** Linux or macOS; a server under `auto`; edit `openssl.cnf` in place (same inode, new size and mtime); run a command under `auto`. If the key covers only the inode, the client computes the old key, reaches the old server, and §5 line 383 refuses the session with "`<file>` changed after the server at `<address>` started; run gwz server --stop" — under `auto`, which the object says cannot happen.
- **Impact.** Either the refusal arises under `auto` (contradicting §5, §14 and §17's "`--server auto` finds a matching server" advice) or the key must be read as the triple, which the text does not say.
- **Required correction.** In §4 line 207 and §5 line 385 write "the identity, size and modification time of each file the scan read, and, on Linux, of the CA bundle", or define "identity" once as that triple.
- **Closure test.** §12's OpenSSL row "a configuration file changed after the start" run under `auto` with an in-place edit: a new server starts and no `server_environment_mismatch` occurs.

### P3-3. Under `auto`, a library session's own timeout can be refused on the timeout row, contradicting "instead of a version or environment refusal", and the message names a CLI flag to a library caller
