## New defects

- **P3 — `impl` and `extern` blocks inside a function body are keyed as statements.** `end(k, braces=True)` now steps over their body and runs on to the next `;`: `fn f() { #[cfg(unix)] impl Trait for X {} go(); }` → `impl Trait for X{}go()`; likewise `unsafe impl Send for X {}`, `extern "C" { fn getpid() -> i32; }` and `unsafe extern "C" { … }` (keys `extern "C"{fn getpid()->i32;}go()`). A braced, rule-compliant item is refused as NEW, and the key absorbs the following statement. Root cause: `target()` handles `impl`/`extern` in neither `BODY_OR_SEMICOLON` nor the braced-statement branch; the accepted object's `end(k)` stopped at `{`. Controls hold: the same `impl` as the block's last item, and `fn`, `struct`, `enum`, `mod`, `trait`, `union`, `macro_rules!` in a fn body give `[]`. No exposure in the trees (the check passes). Fix: return `None` for `impl` and `extern` (after `keyword()`) before the statement branch. Regression test: the four snippets → `[]`.
- **P3 — `async { … }.await;` passes as braced.** `async` is in `BRACED_STATEMENTS`, but an `async` block is an ExpressionWithoutBlock in Rust's grammar (like a closure), so `#[cfg(unix)] async { go().await }.await;` and the `async move` form are `;`-terminated unbraced statements whose deletion orphans the attribute; both give `[]`. Choice 3's never-awaited `async { … };` is harmless, but the awaited form is the one that occurs. 27 files in the trees use `.await` or `async {`; none has a conditional attribute directly on such a statement today. Fix: drop `async` from `BRACED_STATEMENTS` (an `async` block statement is then keyed like any other, with `{ }` stepped over); `async fn` items are unaffected (`keyword()` reaches `fn`). Regression test: the two snippets key `async{go().await}.await` and `async move{go().await}.await`; `#[cfg(unix)] async fn g() {}` stays `[]`.
- **Choice 2 (`const { … }`) — held.** A const block is an ExpressionWithBlock, so nothing can follow its `}` at statement position; it passes via the item path (`const` with no identifier name), and the statement after it is scanned (`#[cfg(unix)] const { assert!(N > 0) }; #[cfg(unix)] next();` → `next()`). Acceptable.

Neither new defect blocks: both are P3, exposure-free today, and each is a one-line change with the test named.
